# 架构与边界

## 模块

| 目录 | 职责 |
| --- | --- |
| `src/` | React 设置页、字幕页、区域选择页；经受限 IPC 调用 Rust |
| `src-tauri/src/` | Windows GDI 截图、ONNX OCR、全局快捷键、托盘、凭据、持久化命令 |
| `crates/core/src/` | 平台无关的档案、文档解析、提示词、Rig 接口、任务竞速和 SQLite |
| `scripts/` | 校验并准备 OCR 资源，收集许可证 |
| `tests/` | 界面流程和虚构 OCR 测试图片 |

## 现场流程

快捷键 → 检查屏幕布局 → 隐去字幕并等待合成 → 读取固定区域 → 本地 OCR → 恢复字幕可见状态 → 文本规范化 → 当前档案版本的准备答案/缓存 → 筛选相关素材 → 单模型或并发调用 → 验证完整文本 → 缓存并显示。

每个问题拥有独立 request ID。状态更新必须匹配当前 ID；切换档案也会使旧任务失效。隐藏字幕不改变 request ID，不取消请求，不清空答案。

现场以短上下文为目标：始终带入个人定位、确认事实、知识边界和回答要求，再按关键词选最多 4 张素材卡、2 条当前版本的准备答案作为参考。原始长文件不在每次回答中重复上传。当前检索为本地关键词匹配，不是语义向量检索。

完整回答到达后一次显示，不把思考内容当回答。空文本、截断输出、接口报错不会成为有效缓存；小幅偏离建议词数不会导致本来可用的回答被丢弃。

## 准备流程

1. 文件导入：本地复制二进制资料，文本/DOCX 提取文本。
2. 逐资料提取：长文本分块；图片/PDF 由用户选择的多模态模型读取。完成的源摘要立即持久化。
3. 汇总：生成定位、确认事实、知识边界、素材卡、来源 ID、待澄清问题和未知项。
4. 用户编辑并补充；重整时复用已提取源摘要。
5. 确认激活：根据整理结果、目标和规则计算 revision。草稿编辑不替换 active。

任务取消阻止后续步骤与结果应用；已发出的 API 请求可能仍在服务商侧完成并计费。重启后运行中任务显示“已中断”，保留完成的文件/答案。

## 接口与数据边界

真实 API 调用仅在 Rust 后端。远程连接要求 HTTPS；仅 localhost 开发接口允许 HTTP。地址禁止携带用户名、密码、query 或 fragment；更改地址需重新填写密钥。禁止自动 HTTP 重定向，避免凭据被转发到意外地址。

SQLite 启用 WAL。档案、设置、连接元数据和任务记录使用 JSON 对象存储，答案有档案/版本/规范化问题索引。API Key 通过系统 keyring 独立保存。密钥不写到档案导出、日志、浏览器状态。

运行时二进制资料使用应用生成文件名，导入路径禁止逃离 sources 目录。文档与问题作为不可信材料，提示词要求忽略其中的操作指令；这并不等同于模型侧绝对的注入防护。

## 延迟与恢复

5 秒软提示与最终超时分开。并发模型只取首个有效完整结果；耗时统计针对回答阶段。OCR 失败提供重试、重新框选、手动输入、显式云端识别四种恢复路径。

屏幕布局发生变化时拒绝沿用旧选区。窗口内容和可见性独立；调整字幕位置不改变问答。

服务商可用性、用户网络、输入长度、模型推理等级和硬件都会影响时延，程序不能保证任何条件下在 5 秒生成真实回答。没有伪造模型输出的兜底文本。
